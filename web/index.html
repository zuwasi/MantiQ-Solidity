Escrow rules

A small, explicit state machine

Before deadline

Buyer may release to the configured supplier.

deadline

At / after deadline

Buyer may refund. Terminal states cannot settle again.

Failed calls leave state and ledger unchanged. Recipient transfer failure must revert settlement.

Intentionally seeded fixture

The authentication defect

Defective

tx.origin == buyer

An intermediary call still carries the buyer as transaction origin.

Corrected

msg.sender == buyer

The immediate caller must be the buyer.

Buyer signs→Untrusted intermediary→Escrow→Configured supplier

Precondition: the buyer signs the intermediary transaction. This is not a remote unauthenticated drain, and funds do not go to an arbitrary thief.

Local EVM

Same path, different result

Defective escrow

Intermediary release succeeds because tx.origin remains the buyer.

Fixed escrow

The same intermediary release reverts because msg.sender is the intermediary.

Additional regressions cover unauthorized direct calls, deadline − 1 versus deadline, second settlement, rollback, and generated action sequences.

Wolfram

Finite transition checks

An independent state-machine implementation enumerates small caller, origin, state, ledger, and boundary-time spaces.

It checks guard behavior, terminal absorption, conservation in the abstract ledger, and the concrete intermediary witness.

Lean

Proofs, with a hard boundary

Lean proves properties of the normalized transition system: rejected unauthorized release, unchanged failed calls, terminal absorption, exclusive time windows, abstract conservation, and the tx.origin counterexample.

Not proved

No correspondence theorem connects the model to Solidity source or bytecode. Gas, external calls, reentrancy, timestamps, ordering, and EVM details remain outside the model.

Olympix

Static analysis integration

The installed VS Code extension is version 2.0.2. CLI authentication is separate and remains pending.

Unavailable access is reported as BLOCKED, not converted into a pass. Credentials are never extracted from VS Code.

SBOMator

Dependency inventory, different claim

SBOMator inventories dependencies and known CVEs. It does not establish Solidity correctness.

Its current result and tool status are linked dynamically in the dashboard evidence rather than frozen into this deck.
